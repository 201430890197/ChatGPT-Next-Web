# 混凝土车辆调度看板(原型 / Demo）

面向商品混凝土企业的车辆调度决策看板原型。聚焦解决两个核心痛点:

1. **不知道哪台车该派给哪个工地** —— 用算法替代"凭经验喊话"。
2. **工地浇筑断料 / 现场压车** —— 实时预警,把供应节奏排匀。

> 规模假设按你们现状设定:**14 台搅拌车、9 名司机**。因为司机是瓶颈,所以同时最多 9 台自有车在跑;当 9 名司机全部满负荷、工地仍要断料时,系统会提示**外调车 / 外调司机**——正好对应满负荷外调的场景。

---

## 怎么运行 / 演示

**零依赖,双击即用。** 用浏览器(Chrome / Edge)直接打开 `index.html` 即可,无需安装任何环境、无需联网。

界面顶部可控制仿真:`⏸ / 1× / 4× / 16×` 调速,`自动调度` 开关,`重置`。
- 打开后默认 08:00 开班、自动调度开启,点 `16×` 可快速看到几小时内 14 台车循环跑、工地供应节奏的变化。
- 关掉 `自动调度`,右侧"派车建议"里点 `立即派车 / 确认外调` 即可手动指挥,体会人工 vs 系统的差别。
- `+工地` 可临时加一个工地(填浇筑速度、总方量),观察运力是否够、是否触发外调建议。

## 调度算法(原型内置逻辑)

### 1. 每个工地需要几台车
```
所需车数 = 浇筑速度(m³/h) × 循环时间(h) ÷ 单车方量(m³)
循环时间 = 装料 + 重车去程 + 现场卸料/泵送 + 空车返程
```
浇得越快、路越远,需要的车越多。看板对每个在浇工地实时算出这个数(见中间"调度算法依据")。

### 2. 错峰发车,避免断料/压车
- **供应间隔** = 单车方量 ÷ 浇筑速度 × 60,即"每隔几分钟应有一台车到场"。
- 系统按这个间隔**错峰发车**,而不是一窝蜂全发出去——这是人工调度最容易犯的错(车扎堆到场 → 压车 → 排队等卸 → 混凝土初凝报废)。

### 3. 断料倒计时 & 压车预警
- **断料倒计时**:根据现场正在卸的车 + 在途重车的预计到达时间(ETA),算出"现有供应还能撑几分钟"。撑不住就标红预警。
- **压车**:现场积压 ≥3 台即预警(1 卸 1 等是正常缓冲,不算压车)。
- **初凝报废**:出罐超过初凝时间(默认 120 分钟)仍未浇完的料,计入"报废(方)"KPI——直观体现压车的代价。

### 4. 何时该外调
当某工地仍缺车、但 9 名司机已全部在岗满负荷时,自有运力已无法覆盖,系统给出**外调建议**(紫色卡片),并说明缺口与断料倒计时。外调不自动执行(涉及成本),需人工确认。

## 关键参数(可调)

在 `index.html` 顶部 `CFG` 对象里:

| 参数 | 含义 | 默认 |
|---|---|---|
| `truckCap` | 单车容量 m³ | 8 |
| `loadTime` | 装料耗时 min | 6 |
| `setTime` | 初凝时间 min(出罐→浇筑上限) | 120 |
| `speedKmh` | 平均车速 km/h | 36 |
| `drivers` | 司机数(=自有运力上限) | 9 |
| `trucksOwn` | 自有车数 | 14 |

工地的距离、浇筑速度、总方量在 `defaultSites()` 里设置。

## 这只是原型:与真实系统的差距

当前版本用**模拟数据**演示调度算法与看板交互。要落地成生产系统,后续路线建议:

1. **接入实时位置**:你们车上已有 GPS / 北斗,把实时坐标接进来替换模拟位置,ETA、循环时间就从真实路况算,不再是估值。
2. **接订单/任务**:对接现有台账或 ERP,工地、方量、浇筑计划自动进系统,而不是手填。
3. **历史数据校准**:用真实运行数据校准装料、往返、卸料时长(不同工地、不同时段差异很大)。
4. **司机端**:司机手机接单、到场/卸毕一键回报,位置与状态更准。
5. **持久化与多人协同**:后端数据库 + 账号权限,多个调度员、多搅拌站协同。
6. **算法升级**:从"按工地需求测算 + 错峰"升级为全局优化(考虑多工地抢车、外调成本、路况预测的统一排程)。

> 技术形态:原型为纯前端单文件,落地时建议演进为「前端看板 + 后端服务 + 位置/订单数据接入」的标准架构,可平滑迁移现有界面。
